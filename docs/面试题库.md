# SpecOps Agent — Agent 应用面试题库

面向「Agent 应用开发」岗位。题目按**产品与设计**出，不假设面试官读过你的仓库，也不问某段代码干什么。

配套设计备忘：[INTERVIEW.md](./INTERVIEW.md)（为什么这样设计）。本文是可直接背的口播稿。

---

## 怎么用

1. 先背下面三块：**项目一句话、三条底线、流水线一句**。开场 30 秒讲完，后面题都往这三块上靠。
2. 标注含义：**高频**（几乎必问）/ **加分**（能拉开差距）/ **防翻车**（答错会扣信任）。
3. 每题先说结论，再给一个会议纪要里的例子，最后主动带一句边界。被追问时不要重复主答案，补「为什么」和「什么时候会坏」。
4. 黄金集分数是**规则路径回归**，面试里不要说成大模型效果。

### 项目一句话

我做的是一个会议纪要 Agent：把中文运维/发布类会议对话，变成带原文证据的任务清单，并且拆出每项的**主责**和**次责**。原文确认不了谁负责时，系统停下来让人分配，而不是填「待指定」。

### 三条设计底线

1. **证据必须是原文连续片段**，不能改写，方便事后对质。
2. **模型建议不等于写入**：负责人候选可以展示，人点确认之前主责保持空。
3. **算不明白就暂停（人工介入）**，占位符看起来完整、实际不可执行。

### 流水线一句

解析目标和干系人 → 缺目标就澄清 → 拆任务并挂证据 → 校验修复（有上限）→ 模型只建议负责人 → 非法或缺人就人工分配 → 终审批准/改/删/重跑 → 导出 Markdown 或 JSON。

编排用 **LangGraph 状态图**；可选 **DeepSeek**；没 Key 走**规则回退**。前端用 **SSE** 推节点级进度。

## 一、开场与产品定位

### Q1. 介绍一下你做的 Agent 应用？（高频）

**你可以这样答**

我做的不是通用聊天机器人，而是一条固定流水线：输入是中文会议纪要，输出是可执行任务清单。每项任务有主责一人、次责可以多人，并且绑一段原文证据。典型场景是发布会前对齐、预发事故复盘、需求评审待办。例如「周婷统筹，孙磊、邓凯配合」，如果只留第一个人名，协作关系就丢了，所以主次责是产品能力，不是展示字段。不确定就停下来问人，导出宁可暂时不完整，也不假装已经分配好。

**可能追问 1：和「贴进 ChatGPT 让它列 TODO」有什么差别？**

**追问怎么接**

聊天一次生成，错了只能再聊一轮，也没有强制证据、没有主次责校验、没有暂停点。我这边是状态图：缺会议目标要澄清，负责人非法要分配，导出前必须终审。校验和修复是确定性规则，模型不能随便改负责人。没 Key 也能用规则跑完整条链路，方便演示和回归，不绑死某一家模型。

**可能追问 2：为什么选会议纪要这个切口？**

**追问怎么接**

会议里同时有「谁做什么」和大量背景闲聊，最容易出现幻觉和责任模糊。把信任做硬——证据子串、主次责、人工拍板——比再做一个能闲聊的助手更能体现 Agent 应用功底。上线缺口也很清楚：还没接真的工单系统，也没有租户鉴权，定位是可演示的 MVP。

---

### Q2. Agent 和聊天机器人，你怎么跟面试官划清？（高频）

**你可以这样答**

聊天机器人的目标是把话说完；Agent 的目标是把一件事做完，并且过程可恢复。我的应用里，模型只负责抽取和建议，真正落责任、修证据、删假任务，靠工具和人工节点。用户看到的是步进条：解析、拆解、校验、分配、审核，而不是一个无限对话框。暂停之后能从断点继续，而不是把整段纪要再贴一次。

**可能追问：那它算不算「自主 Agent」？**

**追问怎么接**

不算开放式自主 Agent。工具集合是封闭的，步骤是预先画好的图，循环有上限。我刻意不用开放 ReAct 让模型自己决定下一步去搜网页、写文件。会议任务抽取的失败成本是「责任安错人」，所以自主性让给可控性。如果业务是调研助手，我才会考虑更开放的规划。

---

### Q3. 为什么一定要拆主责和次责？（高频）

**你可以这样答**

中文会里「负责 / 统筹」和「配合 / 协助 / 推进」经常同时出现。只抽一个负责人，会把配合的人吃掉，导出后无法跟进。产品约定：主责恰好一人，对结果负责；次责可以多人。主次不能是同一个人，次责也不能写成不在干系人里的名字。这样下游按人看看板才有意义：周婷名下是她统筹的项，孙磊名下是配合项。

**可能追问：没有「配合」这种词怎么办？**

**追问怎么接**

没有协作信号就不出次责建议，避免模型为了「看起来完整」乱加副负责人。有模型时，主责已经合法也可能再出次责候选，但只展示，不自动写入。没模型或调用失败，建议为空，流程照样走完，该人工分配还是分配。

---

### Q4. 为什么禁止规则去填「待指定」？（高频 · 防翻车）

**你可以这样答**

「待指定」会让清单看起来每条都有主责，同步到看板或导出后，没人知道这是系统猜的还是会上定的。我的选择是：空主责、主责不在干系人、次责非法、主次冲突、以及消解不了的「他/她」，一律当错误，进入建议再人工分配。人点「提交分配」之前，主责保持空。宁可暂停，也不用占位符伪造闭环。

**可能追问：用户嫌停得太多怎么办？**

**追问怎么接**

停的点要少而准：只在目标空、负责人不合法、终审这三处。证据小问题走自动修复，不打扰人。分配最多三轮，还不行就带着错误进终审，由人显式批准，避免死循环。体验上是「关键处问你」，不是每句话都确认。

---

### Q5. 「证据必须是原文连续片段」解决什么问题？（高频）

**你可以这样答**

会议 Agent 最大的幻觉不是文笔，而是编造一句「会上好像说过」。所以每条任务必须带一段证据，而且必须是输入里连续出现过的子串，不能改写、不能拼接两处。审核的人可以把证据和原文对照；对不上就不是合法任务。这是信任机制，不是为了让 Markdown 好看。

**可能追问：模型喜欢意译怎么办？**

**追问怎么接**

校验工具会打回，修复只允许改标题、验收标准、证据切片这类非负责人字段，不能为了「通顺」去编一句更像人话的证据。修几次还不降错误数就停，进入后面的人工节点，而不是让模型无限改到看起来像那么回事。

## 二、编排与人工介入

### Q6. 为什么用固定状态图，而不是开放式 ReAct？（高频）

**你可以这样答**

这个业务步骤是稳定的：先读懂会，再拆任务，再校验，再认人，再审核。用状态图把节点和分支画死，暂停点、跳过点、重跑点都明确。开放 ReAct 适合工具集不固定、目标要模型自己规划的场景，但这里失败模式是责任错配和假任务，不适合让模型自己决定下一步。状态图还有一个好处：前端步进条可以和节点一一对应，用户知道现在卡在澄清还是分配。

**可能追问：图会不会太死，加一步很痛？**

**追问怎么接**

会，这是权衡。当前节点少、边清晰，终审可以整单重跑或只改一条。若以后要接「同步到工单」，我会加在终审批准之后的确定步骤，仍然不把写外部系统交给开放循环。需要探索的部分（比如从含糊口语里猜任务）放在拆解节点内部，而不是打散整张图。

---

### Q7. 你做了哪几种人工介入？分别什么时候触发？（高频）

**你可以这样答**

三种，都是算不下去或必须人拍板才停。

第一，**澄清**：会议目标抽出来是空的，先问一句「这次会要达成什么」，避免后面任务没有方向。  
第二，**分配负责人**：任一负责人校验失败，包括原文只有「交给她」这种指代消解不了。面板可以展示模型建议，但必须人提交。  
第三，**终审**：看完整清单，批准、改某一条、删掉不是任务的项、或对原文不满意就全文重跑。

人填完再从断点继续，不用从头分析。

**可能追问：三种暂停对前端是不是三套完全不同的状态？**

**追问怎么接**

后端对外可以收成「等人工」，具体是澄清、分配还是审核，用中断类型区分，前端开不同面板。这样 HTTP 状态简单，交互仍精确。澄清走继续对话；分配和审核走恢复执行，带上人的选择。

---

### Q8. 「建议不等于写入」具体怎么落地？（高频 · 加分）

**你可以这样答**

有模型时，即使主责已经合法，也可以跑一轮「负责人建议」：缺主责就给主责候选；有协作信号再给次责候选。置信度只映射成低/中/高给人看，**不按分数自动选人**。人在分配面板点选并提交，或在终审里带上次责建议一起批准，这才写入。没 Key 或模型失败，建议就是空列表，流程不堵死。导出 JSON 时建议字段会剥掉，避免下游把候选当成已分配。

**可能追问：为什么不按置信度自动采纳高分？**

**追问怎么接**

会议上的人名、代词、口头禅，模型很容易「很有信心地指错人」。自动采纳等于把幻觉写进责任链。建议的价值是减少点选成本，不是替代问责。这和搜索排序不同：搜错可以再点，责任写错会进周报。

---

### Q9. 分配一直不合法怎么办？为什么要有次数上限？（高频）

**你可以这样答**

分配最多三轮。还是非法，就带着错误进入终审，让人显式批准或删改；导出阶段不再因为负责人错误拦截——人已经拍板了。没有上限的话，系统和用户会在分配面板里来回弹，这是人工介入死循环。三次是「给纠错机会，但不绑架流程」。

**可能追问：带着错误批准，会不会把脏数据导出？**

**追问怎么接**

会，这是有意的：终审是人的责任面。产品上可以在清单上标红，但不再静默拦死。Demo 里也不自动写外部系统，脏数据出不去工单。若以后接 Jira，批准后应再做一次「仅同步已合法项」或强制补全，那是下一层门，不是在图里无限 interrupt。

---

### Q10. 暂停之后如何保证能接着跑，而不是丢状态？（高频）

**你可以这样答**

要记两件事：业务上「现在清单长什么样、等人填什么」，以及图上「停在哪一个节点」。我用一份应用侧快照给 API 和界面展示，再用图自己的检查点记住光标，这样恢复时知道从澄清还是从分配继续。两次请求还做了幂等：同一个请求号点两下，不会把流水线跑两遍；同一会话正在跑则拒绝并发，避免检查点被踩乱。

**可能追问：只有一份数据库不够吗？**

**追问怎么接**

职责不同。快照面向产品和 API：刷新页面要能还原看板。检查点面向编排：interrupt / resume 必须知道图停在哪一格。缺任一端，要么界面是空的但图还在跑，要么图丢了只能重跑。Demo 用两套 SQLite 分开文件，也方便讲清这个分工；上线可以仍是两种逻辑、同一套存储。

## 三、工具、可靠性与幻觉

### Q11. 模型和工具怎么分工？为什么不让模型直接改负责人？（高频）

**你可以这样答**

解析、拆解、出建议，用模型做结构化抽取。校验、按规则修复、删除明显不是任务的项、导出，是确定性工具。修复**不允许改负责人**——人名是责任，不是文案。模型在校验阶段只能选择调用这些工具，不能自由改写整张清单。这样幻觉被关在「抽取」里，责任链关在「规则 + 人」里。

**可能追问：工具会不会太少，模型施展不开？**

**追问怎么接**

这是封闭工具集。会议抽取不需要搜索、不需要执行 shell。工具少，行为可测，也方便没模型时用同一套规则修不超过两轮。终审里人也能删假任务，规则路径即使没有模型删除，也不会把假阳性锁死在导出里。

---

### Q12. 工具循环为什么必须有上限和「停滞就停」？（高频）

**你可以这样答**

有模型时，校验修复是模型决定调哪些工具的小循环，不是无限 ReAct。往返大约四轮；连续失败两次，或者错误条数不再下降，就视为停滞，立刻停，然后再做一次最终校验。没有上限，模型会在同一条坏证据上反复修，又贵又慢，还可能把标题越改越飘。没模型时规则修复最多两轮，同样封顶。

**可能追问：停早了清单还是脏的，怎么办？**

**追问怎么接**

脏数据交给后面的负责人建议、人工分配和终审，而不是在工具循环里赌模型「再试一次就好」。Agent 可靠性常常不是「循环更聪明」，而是「循环会结束，失败有去处」。

---

### Q13. 没有 API Key 或模型挂了，系统怎么还能演示完整流程？（高频）

**你可以这样答**

整条图有规则回退：解析、拆解、修复都可以不调用模型。CI 和冻结评测强制关掉模型，保证「没 Key 也能跑通」不是口头禅。模型在解析或拆解失败时，留下或合并规则底稿，而不是整单作废。建议节点失败就给空建议。对面试官来说：Agent 应用要把「模型不可用」当成一等公民路径，而不是只做 Happy Path。

**可能追问：规则和质量差很多，会不会误导用户？**

**追问怎么接**

会，所以界面和文档要诚实：无 Key 是确定性演示，有 Key 才是模型抽取。规则漏检弱动词、复姓、英文名，这些我面试会主动讲。不能把规则路径的评测分数说成线上模型效果。两条路径共享同一张图和同一套人工节点，差在抽取能力，不差在「能不能闭环」。

---

### Q14. 你怎么防止「一本正经的幻觉」写进交付物？（高频 · 防翻车）

**你可以这样答**

几层一起挡。证据必须是原文子串；负责人必须落在干系人或等人选；未消解代词当错误而不是猜一个常客；建议不进导出；修复不改人名；终审可以删、可以改、可以整单重跑。长文本也不去假检索一本「公司知识库」往任务上贴，避免检索错再生成错。宁可少一条任务，也不编一条带假证据的任务。

**可能追问：空清单算成功还是失败？**

**追问怎么接**

人在终审里删光并批准，是合法终态，导出会写本次无任务。这比硬塞三条「可能相关」更安全。评测里也把「该停的时候必须停」做成硬指标，停错了比少抽一条更严重。

## 四、明确不做的事

### Q15. 为什么这不是 RAG？长纪要怎么处理？（加分 · 防翻车）

**你可以这样答**

没有向量库，没有知识库问答。任务只来自**这一次粘贴的原文**，不需要检索历史 Playbook。以前如果加过关键词检索展示，我也会拿掉，避免被问成假 RAG。长文本：规则先扫全文打底稿；有模型则按句子边界切块、带一点重叠、并发抽取，再用标题、证据位置窗口、负责人去重。会议目标单独抽一次，再用任务里的人名补干系人。分块换的是成本和延迟，换来的是故事诚实、实现简单。

**可能追问：切块会不会把跨段任务切丢？**

**追问怎么接**

会有风险，所以保留重叠，并且规则底稿不被模型结果整表覆盖。跨段指代本来就会进人工分配。若纪要动辄上万字还要结合「上次发布会决议」，那才值得上检索，而且检索的是**历史决议**，不是这次纪要本身。把切块说成 RAG，是面试里最容易被追穿的点。

---

### Q16. 为什么不做多智能体？（加分）

**你可以这样答**

解析、拆解、建议只是同一条图上的不同节点、不同提示词，不是三个会互相开会的 Agent。多智能体适合目标冲突、需要辩论或分工调用不同工具体系。这里目标单一：抽出可执行且可问责的任务。多 Agent 会多一倍状态、失败和评测成本，却解决不了「他/她是谁」这种必须人确认的问题。

**可能追问：以后拆成「抽取员 + 质检员」两个 Agent 好不好？**

**追问怎么接**

质检我已经用确定性工具做了，比再调一个爱说话的质检员稳。若质检也变成模型，两个模型可能互相让步或互相抬杠，评测更难。只有当质检规则写不清、必须靠经验判断「算不算任务」时，才考虑第二个模型，并且仍要人工终审兜底。

---

### Q17. 为什么不上 MCP 或一堆外部工具？（加分）

**你可以这样答**

MCP 适合把文件系统、浏览器、内部 API 动态暴露给通用 Agent。我的工具是进程内、封闭、可单测的领域动作：校验、修复、删除、导出。没有用户授权模型去连 Jira 或飞书。先把「认人 + 证据」做对，再把「写入外部系统」当成批准后的确定集成，而不是给模型一把万能工具箱。

**可能追问：面试官说现在都在看 MCP，你不会显得落后吗？**

**追问怎么接**

我会说：MCP 是工具暴露协议，不是业务架构。我能讲清何时该用——工具集要跨产品复用、要由模型发现能力时。当前 Demo 的风险是幻觉和错责，不是缺协议。真接企业工具，会先做鉴权、最小权限、人工确认写入，再考虑用 MCP 统一暴露，而不是先上协议再找场景。

---

### Q18. 评测黄金集能不能代表「这个 Agent 很准」？（加分 · 防翻车）

**你可以这样答**

不能。黄金集在**关闭模型**时跑，测的是规则路径回归：图有没有断、该澄清是否澄清、该分配是否分配、关键词能否对上任务。门槛大概是任务召回不低于 0.9，配对上的主责 exact 不低于 0.8，次责集合不低于 0.8，该触发的人工介入必须 100% 触发。这保证改图和改规则不把 Demo 打穿，**不代表 DeepSeek 抽取质量**。有模型的效果要用另一套带人的抽检或线上标注，不能混为一谈。

**可能追问：那你为什么还要黄金集？**

**追问怎么接**

因为 Agent 应用最容易在「加一个节点」时把 HITL 条件改坏。黄金集卡住的是编排契约：代词必须进分配、空目标必须进澄清。没有这层，模型分数再好看，流水线也可能默默填了待指定或跳过终审。

---

## 五、评测、延迟与上线边界

### Q19. 你怎么评价 Agent 好不好，除了「感觉挺聪明」？（加分）

**你可以这样答**

拆成三类指标。第一，**编排契约**：该停不停、不该停乱停，人工介入类型必须对上，这一项我要求全中。第二，**抽取回归**（规则路径）：召回、主责、次责用冻结案例打分，防止重构回退。第三，**产品边界案例**：我会准备不是模板生成的纪要，专门看复姓、英文名、一词多义、弱动词漏检。演示用三个陈述句案例，其中带「交给她负责」的必须走进分配，这是功能不是缺陷。

**可能追问：召回 0.9 是怎么配的？**

**追问怎么接**

用标题关键词重叠来配对，避免同一条 gold 被重复占。0.9 / 0.8 是 Demo 回归线，不是业务 SLA。规则路径对弱动词会漏，所以分数不能对外吹成「准确率百分之九十」。跟业务谈 SLA 时，应单独定义「错责率」和「漏任务率」，并且必须带模型、带真实纪要。

---

### Q20. 规则路径你会主动承认哪些失败？（加分 · 防翻车）

**你可以这样答**

没有「参会人」清单时，规则靠百家姓猜名字，**复姓、英文名**进不了干系人，后面主责会非法或缺失。**「推进」**既是动作又是次责标记，「今天推进一下整体节奏」可能被抽成假任务；规则修复不一定删，但终审可以按全局序号删，按人看板故意不编号，避免和「张三那组第二条」打架。**「交给她」**消解不了是预期成功，必须进人工分配。**弱动词**如「认证模块这周也得有人看一下」会漏；同一人第二句没动作词也不会并成两项。超长语音识别稿按句切块，太大直接拒绝，中等长度提示将分块。

**可能追问：这些失败你怎么补？**

**追问怎么接**

短机能靠模型分块补抽，但规则底稿还在。中期要用户提供参会人名单，比猜姓氏靠谱。假阳性留给终审删除，不在规则里用更狠的关键词误杀真任务。我会把这些当设计债讲出来，比假装规则已经人级更好。

---

### Q21. 进度推送为什么只做到「节点级」，不做逐字思考流？（加分）

**你可以这样答**

图是按节点推进的，一个节点结束才向外刷进度：谁在跑、谁完成、谁跳过、谁在等人工。用户要的是「卡在分配还是审核」，不是看模型逐 token 想。拆解若内部并发多块，也不做块中途推送，避免步进条乱跳。权衡是长节点会有一段「看起来没动」，但状态不会撒谎。真要做流式，应单独流「当前句抽到了什么」，不要和节点状态混在一个通道里。

**可能追问：为什么用服务端推送而不是 WebSocket？**

**追问怎么接**

这是单向进度：服务器推事件，浏览器不需要在同一条连接里双向聊天。SSE 足够、实现简单。人工回复走普通请求恢复执行。若以后要协同编辑清单，再考虑长连接；当前交互是「跑一段 → 停 → 人提交 → 再跑」。

---

### Q22. 如果明天要上生产，你先补什么？现在刻意没做什么？（加分）

**你可以这样答**

刻意没做：真实写入 Jira/飞书、登录鉴权、多租户、限流、密钥托管。前端容器也只是开发服务器级别，不是生产静态托管。同步状态如果界面上有，也只是占位。要上生产我会按风险排：先鉴权和密钥，再「批准后才写外部系统」且可回滚，再把评测从规则回归扩到抽样真纪要，最后才是检索历史决议或开放工具。不把 Demo 包装成已经能进企业流程。

**可能追问：幂等和忙碌保护算不算生产级？**

**追问怎么接**

方向对：防双击、防同一会话并发跑图。但生产还要跨实例锁、超时回收、检查点备份、以及模型超时与限流。我会把现有能力讲成「正确的种子」，不讲成已经高可用。

## 六、你可以反问面试官的三句

收尾用，显得你关心他们的 Agent 怎么落地，而不是背完题就结束。

1. **你们线上 Agent 的人工介入卡在哪一步？** 是确认就执行，还是像我们这样「建议不能直接写责任」？我关心错责的成本谁来扛。
2. **你们怎么评测？** 有没有把「该暂停是否暂停」和「模型抽得准不准」拆开？我们吃过把规则回归分数说成模型效果的亏。
3. **幻觉的可接受度？** 漏一条任务和编一条带假证据的任务，哪个更不可接受？这决定证据校验要不要做成硬门槛。

## 开场 30 秒（可整段背）

我最近做的是一个会议纪要 Agent：输入中文会议对话，输出带原文证据的任务清单，并且拆主责和次责。和聊天机器人的差别是固定流水线加三处人工介入——缺目标要澄清，负责人不合法或「交给她」消解不了要人来选，导出前终审。模型只建议不落责，证据必须是原文连续片段，校验修复有上限。没 Key 走规则回退，黄金集测的是编排和规则回归，不是模型分数。长文本是分块抽取，不是 RAG，也不是多智能体。
