## 面试自我介绍 · SpecOps 段落审校（源码实证）

用户拿来一份面试自我介绍口播稿（含飞致云实习 + SpecOps 会议任务解析 + 旅行规划多智能体），要求评估其中的 SpecOps 段落。

读过的源文件（作为改稿依据）：
- `docs/INTERVIEW.md`、`docs/adr/0001..0007`、`docs/langfuse-observability.md`
- `backend/app/agent/graph.py`（8 节点 / WORKFLOW_NODES / 条件边）
- `backend/app/agent/workflow.py`（SSE + interrupt 检测 + snapshot 落 SQLite）
- `backend/app/api/review.py`（claim_request 幂等 + interrupt_type 校验）
- `backend/app/domain/validation.py`（OWNER_ERROR_CODES、quote_in_source 子串硬约束）

核实到的、可用于面试的硬事实：
- 流水线 8 节点：intake → clarify → decompose → validate_repair → propose_owners → assign_owners → review → finalize
- 5 类 owner ERROR 必须进人工分配：MISSING_OWNER / INVALID_PRIMARY / INVALID_SECONDARY / PRIMARY_IN_SECONDARY / UNRESOLVED_REFERENCE
- evidence_quote 必须是原文连续子串（quote_in_source），不匹配判 INVALID_EVIDENCE_QUOTE
- 工具循环往返上限 4，连续失败 2 或 error 数不下降即 stall 停止；无 Key 走规则修复 ≤2
- 黄金集门槛：任务召回 ≥0.9、主责 exact ≥0.8、次责 set 相等 ≥0.8、HITL 触发一致 100%；且明确「黄金集是规则路径回归，不代表 LLM 效果」
- 可中断可恢复：checkpoint 落 SQLite + `/runs/{id}/resume` + interrupt_id / interrupt_type 防错配
- 幂等：`claim_request(request_id)` 防断网重发双执行
- 可观测：Langfuse 旁路，默认关闭，原文不出网（只传结构 / prompt / usage / 耗时 / 成本）

给出的修改结论：
1. 「负责人分配 + 人工审核」被挤成一项，丢掉了「建议 ≠ 写入」这个最硬机制 → 拆成 propose_owners / assign_owners 并写清触发条件
2. 「无法确认的信息不做模糊填充」太软 → 换成硬约束表述（证据必须原文精确匹配）
3. 「意图澄清」→ 实际是「会议目标澄清」，触发条件是会议目标为空
4. 结构问题：开场立的「可观测 / 可中断 / 可恢复」三个 flag，SpecOps 段一个都没兑现 → 补一句配套（checkpoint 续跑 + 幂等 + 观测旁路）
5. 风险词：「两个智能体落地项目」中的「落地」= 上线生产，SpecOps 属自研作品 → 建议改「从 0 到 1 自研」
